LK

Literature KB

面向 Agent 的科研文献检索、证据核验与引用落地平台

概述

  • papers/search：按标题、摘要、作者、年份等条件发现论文，返回可作为 scope 的 paper_id。
  • evidence/search：用自然语言检索可引用的文献片段，返回 evidence_id、候选正文片段和来源论文。
  • content：按 paper_id 或 evidence_id 读取正文窗口，适合详情页展示、引用核对和长文本分批加载。
  • source：把 evidence 回源到 PDF 页码、bbox 和 asset，适合让 Agent 给出可核验出处。
  • assets：读取或下载论文 PDF、图片、表格、解析图等资源。
  • evidence/packs：对显式 claims 做证据包验证，输出支持、反驳、冲突或未验证结果。
  • citations/ground：对已有 draft 补 citation marker，并返回可验证与未验证内容。
  • tasks / workflows：分别追踪论文处理任务和 Agent 工作流运行状态。

快速开始

最短接入链路建议从检索核验开始：先发现论文，再检索 evidence，然后读取上下文和 PDF 回源。 只有当输入已经是显式 claims 或一段 draft 时，再进入 Evidence Pack 或 Citation Grounding。

papers/search evidence/search content source
curl 去前端体验 
curl -X POST http://127.0.0.1:8000/api/v1/evidence/search \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "evidence that retrieval improves factual accuracy",
    "scope": { "paper_ids": ["paper_123"] },
    "filters": {},
    "top_k": 10,
    "page": 1,
    "page_size": 10
  }'

按领域批量采集并解析入库

OpenAlex Harvest 和本地 Import Pipeline 是两条连续但独立的流水线。先按 Domain、Field、Subfield 或 Topic 枚举并暂存 PDF，再把 staged PDF 批量送入 register、parse、evidence、resource_context、vectorize 和 index。

选择 OpenAlex 分类 下载并暂存 PDF 创建 ImportBatch 解析与索引

管理员准备

在管理控制台的“OpenAlex 采集”添加并检测 API Key；确认 Harvest、maintenance 和各 Pipeline Worker 正常。

普通成员操作

进入左侧“批量采集”，搜索领域、选择分类、设置年份/类型/语言，预估后创建任务。

下载完成

staged 只表示 PDF 已暂存。额度耗尽时任务进入 waiting_quota，重置后自动恢复。

入库完成

registered 还不是 ready；ImportBatch 为 completed 且失败数为 0，才表示整批完成索引。

固定处理阶段打开批量采集
OpenAlex taxonomy → Works → staged PDF
staged PDF → register → parse → evidence
           → resource_context → vectorize → index

API 工具

下面按 Agent 实际调用顺序介绍稳定工具。每个工具都写明输入、输出、适用场景和最小请求示例。 如果只是联调，可以先在前端控制台的 Paper Library、Agent Studio 和 Developer drawer 里手动跑一遍。

POST papers/search POST evidence/search GET content GET source GET assets POST packs POST ground GET workflows

POST /api/v1/papers/search

papers/search 论文发现与 scope 构建

按关键词、年份、作者、DOI、处理状态等条件筛选论文，返回标题、摘要、作者、年份、资源数量和 readiness 信息。

输入

query、filters、sort、page、page_size。

输出

items[]、pagination.total。每个 item 至少关注 paper_id、title、capabilities。

适用场景

为检索、Pack 或 Grounding 先圈定论文范围，生成 scope.paper_ids。

前端体验

进入 Paper Library 搜索论文，勾选行即可形成 Agent Studio 的 custom scope。

请求示例打开 Paper Library
{
  "query": "graphene battery cycle stability",
  "filters": {
    "year_from": 2020,
    "ai_ready": true
  },
  "sort": { "field": "updated_at", "order": "desc" },
  "page": 1,
  "page_size": 20
}

POST /api/v1/evidence/search

evidence/search 智能检索与片段返回

用自然语言提问，返回最相关的可引用文献片段。它适合 Agent 快速找到候选证据，但命中结果还需要继续读 content 和 source。

输入

query、可选 scope.paper_ids 或 scope.evidence_ids、filters、top_k。

输出

EvidenceHit[]，重点看 evidence_id、paper、quote、score、location。

适用场景

RAG 检索、claim 支持/反驳分析、把用户问题转成候选文献证据。

前端体验

进入 Agent Studio，在 Search tab 输入问题并选择 Whole library 或 custom scope。

请求示例打开 Agent Studio
{
  "query": "non-flammable electrolyte for lithium metal batteries",
  "scope": { "paper_ids": ["paper_123", "paper_456"] },
  "filters": {},
  "top_k": 20,
  "page": 1,
  "page_size": 10
}

GET /api/v1/evidence/{evidence_id}/content

content 正文窗口读取

根据 evidence_id 读取命中片段周围的正文窗口，也可以用 paper content 接口读取论文 canonical content。

输入

evidence_id，以及窗口参数 before、after。论文级读取用 offset 和 limit。

输出

EvidenceContentResponse，包含命中片段、前后文、section、paper 信息和定位线索。

适用场景

确认 evidence 是否真的支持当前 claim，给详情页展示上下文，避免只看短 quote。

前端体验

Agent Studio 的搜索结果里点击 Context，即可看到同一接口返回的正文窗口。

请求示例打开 Context 面板
GET /api/v1/evidence/evidence_abc/content?before=1200&after=2400

GET /api/v1/evidence/{evidence_id}/source

source PDF 回源与定位

把 evidence 映射回 PDF 的页码、bbox 和 asset_id，方便 Agent 给出可检查的出处。

输入

evidence_id。

输出

EvidenceSourceResponse，重点看 page、bbox、asset_id、download_url。

适用场景

引用核验、PDF 高亮、回答中给出页码和定位信息。

前端体验

Agent Studio 点击 PDF Source，可预览 PDF 并定位 evidence 来源。

请求示例打开 PDF Source
GET /api/v1/evidence/evidence_abc/source

GET /api/v1/assets/{asset_id}

assets 论文资源浏览与下载

读取 PDF、图片、表格、解析图等资源元数据，或下载具体文件。

输入

asset_id；下载时调用 /download。

输出

资源类型、MIME、文件名、大小、关联论文和可下载二进制内容。

适用场景

展示 PDF、下载论文插图、把 figure/table 资源交给多模态 Agent。

前端体验

Paper Library 进入论文详情的 Assets tab，或在 Agent Studio 打开 Resource。

请求示例打开 Assets
GET /api/v1/assets/asset_123
GET /api/v1/assets/asset_123/download

POST /api/v1/evidence/packs

evidence/packs 显式 Claim 证据包

对一组显式 claims 做检索、核验和证据组织，返回 workflow run。Pack 不接受“只传 evidence_ids 拼包”的旧语义。

输入

claims + scope + filters + top_k_per_claim。

输出

WorkflowSubmissionResponse，包含 run_id。完成后在 workflow result 中查看每条 claim 的 evidence。

适用场景

用户或上游 Agent 已经提出明确判断，需要验证支持、反驳、冲突或未验证。

前端体验

Agent Studio 的 Evidence Pack tab 可以提交 claims 并自动轮询 workflow。

请求示例打开 Evidence Pack
{
  "claims": [
    { "text": "Non-flammable electrolytes improve lithium-metal battery safety." }
  ],
  "scope": { "paper_ids": ["paper_123"] },
  "filters": {},
  "top_k_per_claim": 5
}

POST /api/v1/citations/ground

citations/ground Draft 引用落地

对已有 draft 做 citation grounding，尽量保持原文，只补 citation marker 和验证结果。Ground 不接受调用方传入顶层 claims 或伪造 span offset。

输入

draft + scope + filters + top_k_per_claim。

输出

run_id。workflow 完成后返回 grounded draft、citations、unverified claims 和冲突证据。

适用场景

已有一段研究草稿，需要补引用、标出无法验证的句子，并保留可追溯证据。

前端体验

Agent Studio 的 Citation Grounding tab 可以直接输入 draft 并查看返回结果。

请求示例打开 Citation Grounding
{
  "draft": "Non-flammable electrolytes improve safety in lithium-metal cells.",
  "scope": { "paper_ids": ["paper_123"] },
  "filters": {},
  "top_k_per_claim": 5
}

GET /api/v1/workflows/{run_id}

tasks / workflows 状态追踪

论文处理任务和 Agent 工作流是两套状态体系。paper processing 用 task_id，Pack 和 Grounding 用 run_id。

Task 输入

POST /papers/{paper_id}/operations/{operation}，返回 task_id。

Workflow 输入

POST /evidence/packs 或 POST /citations/ground，返回 run_id。

状态值

queued、running、succeeded、failed。

前端体验

Dashboard 追踪 task；Agent Studio 追踪 workflow run。

轮询示例打开控制台
GET /api/v1/tasks/task_123
POST /api/v1/tasks/task_123/refresh

GET /api/v1/workflows/run_123

Cookbook

检索核验型 Agent

papers/search → evidence/search → content → source。适合回答“有没有文献支持这句话”。

引用生成型 Agent

evidence/packs 处理 claims，citations/ground 处理 draft，再用 workflows/{run_id} 轮询。

灌库处理型 Agent

POST /papers 上传 PDF，再运行 parse、build_evidence、embed 等 operation。

通用规则

  • 鉴权：使用 Authorization: Bearer YOUR_API_TOKEN。内部本地联调可按后端配置决定是否需要 token。
  • 事实源：/openapi.json 是机器可读事实源，这个页面是人类接入说明。
  • 分页：列表接口通常使用 page 和 page_size，总数在 pagination.total。
  • 引用约束：evidence/search 命中只是候选。真正用于引用前，建议继续读取 content 和 source。
  • scope：scope.paper_ids 控制论文边界，scope.evidence_ids 控制 evidence 边界。
  • 错误处理：404 多半是 ID 不存在或 task/workflow 类型混用；422 多半是请求体字段不符合当前 schema。
